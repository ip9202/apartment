# Interview: PARKING 주차 추첨 시스템

## 사전 정정 — 사용자 직접 설명 (도메인 모델 정정)

최초 가정(win/lose 당첨 추첨)이 틀림. 실제는 **slot assignment(자리 번호 배정) 추첨**.

- 모든 세대는 1대의 주차공간을 보장 (탈락자 없음)
- 추첨 = **어떤 자리 번호(위치)를 배정받는지** 결정
- 예: 702호 주민이 14번 추첨 → 14번 자리를 6개월간 사용
- 주차 기간: 관리소에서 변경 가능 (언제부터 언제까지, 주민회의 결정 가능)
- 자리 번호: 관리자가 다시 입력(변경) 가능 — 단, 한 번 정해진 번호는 거의 불변
- 주민이 추첨 버튼을 누르면 랜덤으로 번호 선택 → 선택된 번호가 그 입주민 자리로 입력
- 추첨 기간: 관리사무소에서 설정
- 미참여 세대: 추첨 기간 종료 후 남은 자리 중 랜덤 자동 배정

## Round 1: 핵심 정책 (3 questions)

### Q1: 추첨 동시성/공정성 메커니즘
Question: 주민 동시 추첨 시 "같은 번호 중복 배정 방지" + "랜덤 공정성" 보장 방식
Answer: **회차 seed 기반 결정론적 순열 (권장)**
- 회차 생성 시 seed 1개로 전체 자리 배정 순열(unit_id → slot)을 결정론적 생성
- 주민 버튼 클릭 시 자기 unit이 순열에서 가리키는 자리 즉시 확정(공개)
- 순서 무관 (먼저/나중 누르든 동일 결과)
- 동시성 충돌 원천 불가 (미리 정해진 순열)
- seed + 순열 공개로 누구나 재현 검증 가능
- product.md "랜덤 시드와 당첨 결과 공개로 공정성 보장" (product.md:154)과 완벽 부합

### Q2: 자리 수 / 번호 체계
Question: 주차 자리 수와 번호 체계 (seed 38세대 기준)
Answer: **직접 입력 (사용자 커스텀 선택)**
MoAI 해석 (Plan Review에서 재확인 필요): **관리소가 회차 생성 시 자리 번호 풀(목록/범위)을 직접 입력하는 동적 슬롯 모델**. 시스템 고정 1~38 아님. 회차마다 자리 번호 세트를 관리소가 정의. 이 해석이 세대수=자리수, 여유 자리, 동별 분산 번호 등 모든 변형을 유연하게 수용.

### Q3: 회차 전환 / 미참여 자동배정
Question: 회차 전환과 미참여 자동배정 시점
Answer: **관리소 수동 트리거 (권장)**
- 관리소가 회차 생성 (추첨 기간 설정)
- 주민이 추첨 버튼으로 자리 확정
- 기간 종료 후 관리소가 "자동배정 실행" 버튼 클릭 → 미참여 세대 남은 자리 랜덤 배정
- 이전 회차 만료 시 새 회차 생성으로 전환 (예: 6개월 주기)
- 관리자 통제 명확, 운영 유연

## 도출된 도메인 개념 (Research/Planning 입력)

- **Round(회차)**: 관리소 생성, 추첨 기간, 자리 풀(관리소 입력), seed(결정론적 순열 원천)
- **Slot(자리)**: 번호 식별, available/assigned 상태
- **Draw(추첨)**: 주민 버튼 클릭 → seed 순열에서 본인 자리 확정. 세대당 1회(유니크 unit_id per round)
- **AutoAssign(자동배정)**: 관리소 트리거 → 미참여 세대 같은 순열에서 배정
- **Assignment(배정)**: unit + slot + 기간(from~to). 거의 불변, 관리자만 재입력
- **Transparency**: seed + 순열 알고리즘 + 입력(정렬 unit 목록) 공개 → 재현 검증

## 역할 매트릭스 (product.md 기준)
- **RESIDENT**: 회차 조회, 추첨 버튼(자리 확정), 본인 배정 결과 열람
- **관리사무소(ADMIN)**: 회차 생성(기간+자리풀+seed), 자동배정 실행, 번호 재입력, 기간 변경, 결과 공개
